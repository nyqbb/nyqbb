## 🧠 超级智能

当前专注：**超级智能（ASI）**。

超级智能由两个引擎组成：

| 引擎 | 做什么 |
|---|---|
| ⚙️ **执行引擎** | 负责单条输入的执行与结果产出。 |
| 🧭 **任务引擎** | 负责任务的创建、驱动、确认与归档。 |

> 内部规则和实现细节放在项目文档中，主页不展开。

## 📚 理论依据：引用来源与顺序

本项目的执行引擎、任务引擎与整体架构，不是另起一套体系，而是依次参照以下著作与文件中的统一逻辑展开：

### 一、总纲与导读

- **《大道至简·以简驭繁》**  
  纪元哲学体系导读，说明《大道至简》与《以简驭繁》两大系列的关系、阅读路径与体系定位。

### 二、《大道至简》系列（理论构建）

1. **《大道至简·纪元定则》**  
   元规则奠基卷。提供第一性原理、符号系统、运算规则与人工智能元规则。

2. **《大道至简·纪元时空》**  
   理论基础卷。提供“禀赋—间域—能量”三原理论框架与万物操作系统模型。

3. **《大道至简·纪元宇宙》**  
   体系深化卷。提供符号系统、递归框架与东西方智慧融合的认知宇宙。

4. **《大道至简·纪元生命》**  
   专业应用卷。提供生命领域的象数推演与辨证体系。

### 三、《以简驭繁》系列（实践展开）

5. **《以简驭繁·纪元医道》**  
   实践应用卷。以阴阳五行、藏象辩证、四诊合参、方剂同治展开同一套逻辑。

### 四、项目文件

6. **《超级人工智能执行引擎方案》**  
   本项目直接依据的工程架构文件，定义执行引擎与任务引擎的职责、主链与边界。

### 引用关系

- 上述著作共用**同一套纪元定则与法则**；
- 《超级人工智能执行引擎方案》是这套逻辑在工程层面的展开；
- 执行引擎、任务引擎不是另立体系，而是对同一逻辑的功能拆分与实现。

## 📍 项目定位：项目从超级智能开始，也以超级智能结束

当前主流开源项目，通常先造一个工具、平台、操作系统或推理内核，再声称“未来通向”超级智能：

- **OpenCog Hyperon** 先做 AGI 研发平台，再向超级智能扩展。
- **WolfCog** 先做符号操作系统，定位为 AGI 的 meta-root。
- **Noor Core** 先做实时符号推理系统，作为 transformer 的替代 runtime。
- **PrologAI** 先做认知架构 / 合成心智平台。
- **formal-ai** 先做 GOFAI 传统的确定性符号助手。
- **Horismos** 先做神经符号决策内核。

它们共同的路径是：**先造载具，再声称通向超级智能，未来再扩展。**

本项目不设“先造工具、再通向超级智能”这一段。

项目的对象从一开始就是**超级智能**本身，不是通用人工智能，也不是任何“通往超级智能的中间工具”。执行引擎和任务引擎不是通往超级智能的载具，而是超级智能本体的两个组成部分。

项目从超级智能开始，也以超级智能结束：起点是超级智能，终点也是超级智能。中间做的是把超级智能的执行结构展开、定义清楚、实现出来。

> 这不是技术路线上的高低之分，是**项目对象**的不同：  
> 它们在造通往超级智能的载具，本项目在直接定义超级智能自身的执行结构。

## 🧭 技术路线

本项目属于 **符号主义** 路线：用显式规则表示知识，按规则执行，过程可追溯、可审计。  
与当前主流的大模型生成路线不同，本项目不依赖运行时生成，而是靠规则执行和结果回放。

理论依据来自上述**纪元哲学体系**的统一逻辑，而非临时拼凑的外部框架。
